# Генератор КП по SEO — Qmedia

Внутренний веб-инструмент для отдела продаж Qmedia: по параметрам проекта формирует
коммерческое предложение по SEO — считает стоимость и часы по 5 направлениям, отдаёт
**PDF** (КП для клиента) и **Excel** (план + расчёт) и сохраняет каждую генерацию
отдельным JSON на сервере (можно открыть и пересчитать заново).

## Возможности

- Визард ввода параметров проекта с живым расчётом стоимости.
- 5 направлений SEO (Коммерческое, Информационное, GEO, SERM, Техподдержка) — в КП всегда
  присутствуют все, с пометкой «включено / не входит». Внутри можно убрать работы из
  каталога или добавить свои.
- Расчёт стоимости и часов по алгоритму из `sources/Расчет SEO.xlsx`.
- Экспорт в **PDF** (A4 landscape, фирстиль Qmedia) и **Excel** (2 листа: «Расчёт» и
  «План работ»).
- Сохранение КП в JSON, список сохранённых, импорт ранее сохранённого JSON с пересчётом.
- Отдельный шаг **«Менеджер»**: выбор контактного лица из справочника (или ввод вручную) —
  эти данные попадают на обложку PDF и в блок контактов.
- Раздел **«Настройки»** (шестерёнка в шапке): все ставки и коэффициенты расчёта правятся
  через интерфейс, там же ведётся справочник менеджеров.

## Стек

Next.js 14 (App Router) · TypeScript · Tailwind CSS · `@react-pdf/renderer` (PDF) ·
`exceljs` (Excel) · `zod` (валидация) · `vitest` (тесты).

## Запуск

Требуется Node.js 18+. Хранилищу нужен Postgres — см. [Хранение данных](#хранение-данных).

### Быстрый старт через Makefile

Поднимает локальный Postgres в Docker и dev-сервер одной командой:

```bash
make init     # зависимости + .env.local + контейнер Postgres (один раз)
make dev      # dev-сервер в foreground (live-логи, Ctrl+C — выход)
# либо фоном, чтобы потом управлять:
make start    # БД + dev-сервер в фоне (логи: make logs)
make restart  # перезапустить окружение
make stop     # остановить dev-сервер и БД (данные сохраняются)
make status   # что сейчас запущено
make help     # все команды
```

### Вручную (npm)

```bash
npm install
npm run dev      # режим разработки → http://localhost:3000
# сборка и прод-запуск:
npm run build
npm start
npm test         # юнит-тесты расчёта (включая «золотой тест» из Excel)
```

> Если порт 3000 занят, Next выберет следующий свободный (например 3001) — смотрите
> сообщение в консоли.

## Как работает расчёт

Логика повторяет `sources/Расчет SEO.xlsx`. Значения по умолчанию — в
[`lib/seo-config.ts`](lib/seo-config.ts), сама формула — в [`lib/calc.ts`](lib/calc.ts):

- Базовая стоимость `750`, стоимость часа `75` BYN.
- Цена направления за месяц = `base × коэф.направления × произведение применимых коэффициентов`,
  округление до целого. Часы = `round(цена / 75)`.
- Наборы коэффициентов у направлений различаются (Коммерческое/GEO используют все,
  Информационное/SERM — без страниц/ошибок/конкуренции, Техподдержка — только
  страницы/ошибки/опыт).
- Итог за месяц — сумма по включённым направлениям; итог за проект = месячный × срок (3 или 6).

Ставки и коэффициенты меняются **в интерфейсе** — «Настройки → Данные для расчёта»
(см. ниже). Значения по умолчанию и варианты ответов (список регионов, вариантов страниц
и т.п.) живут в `lib/seo-config.ts`. Перечень работ по направлениям —
[`lib/works-catalog.ts`](lib/works-catalog.ts).

## Настройки

Кнопка-шестерёнка в шапке (`/settings`), две вкладки:

- **Данные для расчёта** — базовая стоимость, стоимость часа, коэффициенты направлений,
  какие коэффициенты параметров участвуют в формуле каждого направления, пакетная скидка
  (направление-триггер, получатели скидки, процент) и все таблицы коэффициентов параметров.
  Каждое поле снабжено пояснением; есть кнопка сброса к значениям по умолчанию.
- **Список менеджеров** — Имя Фамилия, специальность, телефон, email. Добавление,
  редактирование и удаление. Этот список предлагается на шаге «Менеджер» в визарде.

Важно: **изменение настроек не затрагивает уже сохранённые КП**. Каждое КП хранит копию
настроек, по которым его посчитали, поэтому его PDF и Excel всегда дают те же цифры, что
были при отправке клиенту. Чтобы пересчитать старое КП по новым коэффициентам — скачайте
его JSON и импортируйте заново.

Не меняются через интерфейс (завязаны на типы и вёрстку): валюта (BYN), варианты срока
(3 и 6 месяцев), сами варианты ответов в форме, названия и порядок направлений.

## Хранение данных

Каждое КП хранится строкой в таблице `proposals` Postgres (Neon/Supabase): `id`,
`created_at` и весь объект КП в колонке `data jsonb`. Подключение задаётся переменной
окружения `DATABASE_URL` (см. [`.env.example`](.env.example)); таблица создаётся
автоматически при первом запросе. JSON содержит введённые параметры, выбор
направлений/работ, контакты менеджера, снимок расчёта и снимок настроек, по которым он
сделан. При генерации PDF/Excel расчёт выполняется заново из параметров, но по снимку
настроек этого КП; при импорте JSON — по текущим настройкам.

Настройки приложения лежат в той же БД, в таблице `app_settings` (ключ → `jsonb`): `calc` —
параметры расчёта, `managers` — справочник менеджеров. Таблица тоже создаётся автоматически.

Для локальной разработки достаточно любого Postgres (например, в Docker):

```bash
docker run -d --name seocp-pg -e POSTGRES_PASSWORD=test -e POSTGRES_DB=seocp \
  -p 5432:5432 postgres:16-alpine
echo 'DATABASE_URL="postgres://postgres:test@localhost:5432/seocp"' > .env.local
```

### Деплой на Vercel (бесплатно)

1. Подключить репозиторий на [vercel.com](https://vercel.com) (импорт из GitHub).
2. Завести бесплатный Postgres в [Neon](https://neon.tech) или [Supabase](https://supabase.com).
3. В настройках проекта Vercel задать переменную окружения `DATABASE_URL` —
   **pooled/pooler** строку подключения (см. комментарии в `.env.example`).
4. Деплой. Таблица создастся автоматически при первом сохранении КП.

Данные живут в БД (вне репозитория и вне эфемерной ФС хостинга), поэтому переживают
передеплои и не теряются — в отличие от прежнего файлового хранилища.

## Брендинг и шрифты

- Фирстиль Qmedia: основной цвет — **зелёный** `#53BD35`, акцент — **жёлтый** `#FFDE00`
  (сверены с CSS qmedia.by). Чёрный почти не используется. Палитра — в
  [`lib/company.ts`](lib/company.ts) (`BRAND`) и `tailwind.config.ts`.
- Логотипы (`public/brand/logo-*.svg`) — из Figma-стайлгайда Qmedia: вордмарк и знак-кружок
  в белом/зелёном/чёрном вариантах. В вебе используются SVG; в PDF — белые растровые
  (`qmedia-*-white.png`), т.к. `@react-pdf/renderer` не грузит SVG через `<Image>`.
- Корпоративные фото — `public/images/print-*.jpg` (используются на обложке PDF).
- Оформление PDF повторяет референс `sources/cp-development.pdf`: зелёный заглавный слайд
  с фото и логотипом, зелёный градиентный колонтитул с Q-watermark на каждом слайде,
  отдельный слайд «Смета», жёлтые акценты.
- Шрифт — PT Sans (OFL, с кириллицей) в `public/fonts/QmediaSans-*.ttf`: в PDF
  регистрируется в `ProposalPdf.tsx`, в вебе подключён через `@font-face` в `globals.css`.

## Принятые решения и допущения

- **Валюта** — BYN. **Срок** (3/6 мес): расчёт Excel — стоимость за месяц, итог = месяц × срок.
- Поля **«Ссылочное продвижение»** и **«Конкуренция»** добавлены в форму (есть в Excel).
- **«Что продвигаем»** не влияет на цену (нет такого коэффициента в Excel) — используется
  как текстовый параметр.
- Вариант **«до 500» страниц** в исходном Excel отсутствует — задан коэффициент `1.1`
  (между «до 50»=1.0 и «до 1000»=1.2), правится в настройках.
- Авторизация для MVP не реализована (внутренний инструмент) — раздел настроек тоже открыт.
- Сохранённое КП неизменяемо: правка настроек и справочника менеджеров на него не влияет.
- Нумерация страниц в PDF не выводится (динамические узлы `@react-pdf/renderer` в связке
  с бандлингом Next не дают вывода) — подвал содержит название компании и сайт.
